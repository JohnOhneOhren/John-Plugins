# 微信读书笔记 · Codex 插件 0.7.1

抓取提速：同一章节的原文位置默认每 5 个合并查询，分别保留分页游标和覆盖统计，接口返回不完整时自动退回单条查询。点赞状态仍逐条向官方详情接口核验，不复用上次状态，不缩小扫描范围。可用 `--review-batch-size 1` 关闭合并查询；批量查询不等于全书点赞记录完整。候选很多时，逐条核验仍需要时间。

选书、时间、导出目标与结果都在 Codex 对话中完成，程序在后台运行，不打开 PowerShell 窗口，也不会要求在终端重复输入书名。需要有本地执行能力的 Codex 和 Python 3.10+；仅云端执行的聊天不能调用这套本地工具。

## 安装与开始

在支持仓库插件市场的 Codex 客户端中添加 https://github.com/JohnOhneOhren/John-Plugins ，安装 weread-notes，然后新开对话：

> 使用微信读书笔记插件，把《不开玩笑》的笔记导入我指定的 Notion 页面，不显示日期。

插件会后台检查 Python 与依赖，必要时在独立虚拟环境安装。选项已在消息中明确就不会重复问。依赖安装或本地访问权限提示仍由 Codex 的权限设置决定，这不要求另开 PowerShell。

## 首次授权，无需终端

首次运行会先检查本地 Python 与所选导出方式的依赖。缺少本地库时，在用户目录创建独立环境并后台补齐；无需安装 Microsoft Word。选择 Notion 时，会检查当前用户是否安装并连接官方 Notion 插件：未安装则主动展示宿主安装入口，已安装但未连接则引导连接；完成后再次验证，才开始抓取和导入。账号授权须本人完成。Word 导出不需要 Notion。没有本地执行器、安装被组织禁用或网络失败时，会说明实际阻碍，不假装已安装或已导入。

1. 插件先检查已有环境变量或本地加密授权。
2. 首次授权先明确询问是否长期记住 Key：选择“本机加密长期保存”或“临时使用 30 分钟”。没有选择时不会擅自保存。旧版已有可读取授权但没记录过选择时补问一次，可以直接调整保存偏好，无需再发送 Key。已有明确选择的有效授权不会每次重复问。
3. 没有授权时，再独立提示输入 Key，附官方页面 https://weread.qq.com/r/weread-skills 。用户登录后，将自己的 `wrk-` Key 发送到 Codex 对话中。Key 会保留在聊天历史，插件不会假装这是隐藏密码输入框。
4. 发送 Key 且已选择保存方式后，插件立即后台验证并加密保存，不需要再发送“确定”。如果还没选保存方式，只补问保存偏好，选择后直接继续。
5. 授权成功后才显示书架，继续询问选书、Word/Notion、日期和具体位置。已给出且能唯一匹配的书名直接使用，不再去终端输入。

默认不读剪贴板；用户主动要求时仍可选择剪贴板兼容方式。聊天 Key 通过后台进程的 stdin 管道传入，不放进命令行参数或明文临时文件。宿主后台无法传递管道或无本机权限时，会说明限制，不偷偷改为剪贴板或弹出终端。

Windows 下选择长期记住授权，会用 DPAPI 当前用户保护加密保存到用户数据目录，不设本地过期时间；选择临时才缓存 30 分钟，没有选择不会静默采用默认。本机长期保存不代表微信读书服务端保证 Key 永久有效。不同 Windows 用户、不同电脑或不同执行身份可能无法解密，需要重新授权。插件不以明文保存 Key，也不会把 Key 放入命令行。已有 WEREAD_API_KEY 环境变量优先使用。非 Windows 暂不提供加密存储，仍可用预先配置的环境变量；不自动降级为明文存储。

在对话中说“清除微信读书授权”，插件即可删除加密记录；若授权来自环境变量，会提示用户另行清除。Key 过期或失效时重新授权，不循环弹窗。浏览器不需要一直开着，仅登录 Edge 本身不会给插件授权。

Notion 使用当前用户自己的已连接账号；首次按 Codex 的连接流程授权目标页面，不需要在 PowerShell 输入 Integration Token。没有连接时在对话中引导连接，不擅自改用旧终端向导。公共 notion-client API 路径仍留在单文件脚本供开发者独立使用。

## 导出与范围

Word 保存到用户选定的现有文件或新建文件夹，在对话中给出文件链接；不自动替用户选择目录。Notion 计划先保存到本地，再通过用户连接导入；计划含私人笔记，不上传至发布仓库。

选择 Word 后会明确问：“更新现有 Word 文件，还是选择文件夹新建？”更新现有文件需要具体 .docx 路径；新建需要目标文件夹，默认文件名为《书名》- 读书笔记.docx，重名另存而不覆盖。可以说“上次那个文件”，能唯一确认时不会重复追问。没有确定目标前，不会抓取或写文件，也不会偷偷选中上次文件。

Notion 使用普通正文、章节横线、标题后空行，每条摘抄后另留一个真实空段落；“我的想法”“读者观点”挂在对应原文评论中。直接写入页面、子页和数据库记录分别选择；“导入某页”默认为写入正文。公共 API 只能新建块评论，支持选区的连接器可以新建文字选区评论。

选择显示记录日期时，Word、Notion 正文及批注统一使用纯数字普通文本 `（YYYY-MM-DD）`，例如 `（2024-05-21）`。不使用 Notion 日期提及、@May、英文月份或“今天”等相对时间。旧笔记里的智能日期按其底层原始数值转换，不改变实际日期；Notion 自身界面显示的创建/修改时间不属于插件写入的记录日期。

点赞观点来自个人笔记、热门划线及官方章节划线位置中的候选，并逐条通过官方单条详情核验。默认核验全部已发现候选，不再发现 1000 条就提前停扫，也不再只核验前 200 条；候选较多时会更慢。各章轮流安排范围，每个范围轮流翻页，避免前几个热门段落独占预算。默认仍有 500 个范围、1000 个请求页的保护上限，不能保证覆盖全书全部点赞，达到上限会给出实际覆盖统计。想法本身的分享链接可以直接补查，仍会检查当前点赞状态和所属书籍。

导出结果包含 liked_scan 和不含正文/凭证的 `.liked-scan.json` 范围报告：已知/访问/读完范围、候选数、核验数、未核验数、失败数和确认点赞数。范围内读完也不能称为全书点赞完整。需要限制耗时时可明确选择正数 --max-review-checks；0 表示核验全部已发现候选。用 --max-review-ranges/--max-review-pages 调整范围和页数保护上限，不能悄悄选择快速限额后声称完整。

## 读到一半和读完后的再次同步

默认增量同步：读到一半导出一次，读完再导出到同一 Notion 页或同一个 Word 文件时，旧原文和旧评论保留，仅添加新划线、新想法和新点赞观点。已有原文下新增的评论会关联到已有原文，不重复抄录这一段。不同章节分别去重，改变日期显示选项不会把旧记录当成新增。

Notion 会重新读取目标页完整正文和全部评论后再对比。微信读书仍有、但 Notion 目标页已删除的笔记或评论会补回，不再因旧回执标记而跳过；仍存在且能识别的手工改写不会覆盖，定位不清楚时在对话中确认。明确说“保留我在 Notion 的删除状态”才不补回删除项。旧版没有回执的笔记先按同章精确文本匹配。正文或评论读取不完整时暂停，避免把读取失败当作删除。留白也会检查，已有空行不重复叠加。

Word 更新用户选定的现有文件，保留旧文字、手工笔记、字号、颜色、间距、图片和表格等，不重新生成整份文档，不再自动调整旧段落的留白；既定空行和排版只用于新增笔记。旧内容精确去重，新想法关联对应原文；无章节样式的旧手工文件也可按唯一精确原文沿用，歧义时先确认。写入前保留 .before-sync.bak 备份。旧文件移动或路径不明确时在对话中选择，不能自动创建替代文件。微信读书端删除笔记或取消点赞不会自动删除已导出的旧内容。

例：“我读完《不开玩笑》了，把新增笔记补到上次那一页，原有内容保留。”完成后会报告保留和新增数量；无新增则不写入目标。

## 升级

升级整个插件及 Skill 需要刷新 Codex 的仓库插件市场并更新安装，新开对话。旧对话可能仍加载旧版本的终端/剪贴板向导说明，必须新开对话使用新版。

运行代码更新器保留 `updates configure/check/apply/rollback`，可由 Codex 后台执行，不需要用户打开终端。自动升级默认关闭，发布者配置真实 release.json 后才可启用。HTTPS 和 SHA256 校验后切换版本，回滚关闭自动更新；不覆盖笔记或授权。更新依赖需完整升级。

微信读书或 Notion 接口变化需要维护者验证、修复并发布新版本，更新器不会凭网页内容自行重写代码。当前尚未配置远端更新源，GitHub 仓库分享不等于公开目录上架。
